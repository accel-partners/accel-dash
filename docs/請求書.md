# 請求書（基幹システムの「請求書」画面）

基幹システム（crm.accel-dash.com）の `#/invoices` から、このアプリの `/api/invoices` を呼ぶ。

1. 下書き：基幹システムの取引商品（毎月定額・その月のスポット）と、アドマネージャーの `/api/billing`（媒体費・月予算・手数料）から、顧客ごと・月ごとに `crm_docs` の `invoices/inv-<YYYY-MM>-<顧客ID>` を作る
2. MF に作る：クラウド請求書 API `POST /invoice_template_billings`（インボイス対応の新形式）。請求書番号・PDF・宛先の会社名と住所は MF のまま
3. 送る：MF の PDF を添付して SMTP で送る（送付先は MF の部門のメールアドレス、顧客の請求設定で上書き可）
4. MF に作った請求書は、毎朝の同期（lib/mfSync.ts）で売上（revenues）と未入金（receivables）に入る。作るときに `meta/mfmap` に取引先名 → 顧客 を足す

- 顧客ごとの設定：`crm_docs` の `billing/<顧客ID>`（送り方 auto/confirm・広告の請求方法・支払期限・宛先・MF の部門・入れない取引商品）
- メールの文面：`crm_docs` の `meta/invoicing`
- MF の取引先の控え（1 時間）：`crm_docs` の `meta/mfpartners`
- 使える人：基幹システムを使える人（`requireAppUser(req, 'crm.accel-dash.com')`）
- 二重作成の防止：MF に送る前に `status: creating` を書く。応答が返らずに失敗したら `creating` のまま止め、人が MF を確かめてから「やり直せるように戻す」
- cron では動かさない（人がボタンを押したときだけ）

## Vercel の環境変数（accel-dash）

| 名前 | 中身 |
| --- | --- |
| `BILLING_API_SECRET` | アドマネージャーと同じ合言葉（24 文字以上のランダムな文字列）。accel-admanager にも同じ値 |
| `ADMANAGER_URL` | 省略時 `https://admanager.accel-dash.com` |
| `SMTP_HOST` / `SMTP_PORT` | 送り元のメールサーバー（Google Workspace なら `smtp.gmail.com` / `465`） |
| `SMTP_USER` / `SMTP_PASS` | 送り元のアカウントと、アプリ パスワード |
| `MAIL_FROM` | 差出人（例：`株式会社アクセルパートナーズ <keiri@accel-partners.co.jp>`） |
| `MAIL_BCC` | 控えを送る先（省略可。送り元と同じアドレスにすると受信箱に控えが残る） |
| `MAIL_REPLY_TO` | 返信先（省略可） |

MF の書き込みスコープ `mfc/invoice/data.write` を足したので、一度「マネーフォワード連携」で接続し直す。
